# 在管理页调试真实接口

[English](../../docs/debug.md) · **简体中文**

读完本页，你能在管理页的「调试」页维护一组真实接口请求，用环境变量填充它们，并知道它写出的哪些文件该提交。调试页地址是 `/__mock/debug`。

## 用分组管理请求

左栏列出分组和请求。用「请求」和「分组」按钮在顶层新建，或用分组旁的按钮在分组里新建；铅笔按钮编辑节点，垃圾桶按钮删除节点。

- 名字可以包含字母、数字、中文、`.`、`_` 和 `-`，最长 64 个字符，首尾不能是 `.`、`_` 或 `-`。比较名字时不区分大小写，所以同一分组里不能同时有 `User` 和 `user`。
- 节点可以设置展示名和权重；权重大的排在前面，权重相同时按名称排序。
- 编辑节点时还可以把它移到其他分组，并设置它自己的变量。

## 编写请求

选中一个请求后，可以编辑方法、URL、查询参数与路径参数、请求头、认证、请求体和设置，然后点「保存」。

```text
{{baseUrl}}/api/user/:id
```

- `{{name}}` 会被替换成变量的值；URL 里的 `:id` 取同名路径参数的值。
- Bearer Token 和 Basic 认证会自动加上 `authorization` 请求头；你自己写了这个头时以你写的为准。
- 请求体可以是 JSON、文本、URL 编码的表单、multipart 字段或文件；文件路径相对 mock 目录。
- 「设置」里有超时、是否跟随重定向、是否跳过 HTTPS 证书校验、HTTP 代理，以及这个请求对应的 mock 路由。
- 「解析预览」显示最终的 URL、请求头、每个变量的来源，以及没能解析的变量。

如果别人先保存了同一个请求，你的保存会失败，并提示重新加载。

## 发送请求并查看响应

点「发送」按编辑器里当前的内容发送请求，保存与否都可以；「取消」中止发送。请求由 mock 服务发出，所以不受跨域限制，真实的 `cookie` 与 `authorization` 请求头也能发出去。

- 有无法解析的变量时不会发送，先在环境组或请求里补上。
- 压缩的响应（gzip、deflate、br，以及 Node 支持时的 zstd）会解压后保存。响应体最多保存 50 MB，超出部分截断并标注。
- 结果里有状态码、耗时、大小、响应头、实际发出的请求头和响应体：JSON 会格式化，HTML 在不允许脚本的沙箱里显示，CSV 显示成表格，图片直接显示，其他内容可以下载。
- 超时、连接被拒和取消的请求也会记录，并带上错误码。

默认只有本机能发送。要让局域网设备借本机发送，先在页头打开「局域网」，再打开「代发」；见[放行其他主机、局域网与跨域页面](security.md#从其他机器打开管理页)。

## 保留与清理历史

每次发送都保存为一条历史，在请求下方和「全部历史」页都能看到。历史按天存放；某天超过 50 MB 后，当天之后的记录改为按小时存放。

历史不会自动删除。总量达到 1 GB 时，每个管理页都会提醒；在「全部历史」页可以看到每天的大小，并按天删除。

## 把结果另存为命名快照

想保留的历史可以另存为所属请求的命名快照：在结果旁点「另存为快照」，起一个 `ok`、`empty` 这样的名字，它就出现在左栏该请求的下方。之后 mock 场景用的就是快照，所以名字要能说明是哪种情况。

- 名字已存在时（不区分大小写）会先确认再覆盖；被覆盖的快照保留原来的展示名、权重和快照变量。
- 快照可以有自己的变量，它们优先于请求、分组和环境组的变量。「按此快照重新发送」会用这些变量发送已保存的请求，例如换一个 id 再抓一次同样的调用。
- 每个快照是一个目录，里面是 `__meta__.json` 和响应体文件 `raw.<ext>`；扩展名跟随 `content-type`，所以可以直接打开 `raw.csv` 或 `raw.html`。

## 对比与刷新快照

快照上的「刷新」会用快照变量重新发送它的请求，并在保存前展示差异：状态码、不同的响应头，以及响应体的逐行 diff。JSON 响应体会先按 key 排序再比较，所以只是 key 顺序不同不算变化；数组顺序变化算。点「用新结果覆盖快照」保留新结果，或点「放弃」。

要对比两次发送，在请求的历史里勾选两条。二进制响应体以及超过 2 MB 的响应体只比较大小和校验值。

## 把快照用作 mock 场景

在路由的「场景」标签页用「从调试快照建」，可以引用或拷贝快照，见[切换场景与响应方式](scenes.md#用调试快照作为场景)。快照面板会列出使用它的场景。

- 请求、分组或快照改名或移动时，引用它们的场景会自动改写。
- 删除被场景引用的快照、请求或分组前会先确认，并列出这些场景；确认后它们会降级到下一级场景。
- 请求的「设置」里会按解析后的 URL 推荐匹配的 mock 路由，没有时可以直接新建。

## 导入导出 cURL 与 OpenAPI

请求列表顶部和每个节点旁边的按钮用来导入导出：

- **cURL**：粘贴一条命令（例如 Chrome 的 Copy as cURL (bash)）生成请求。支持单引号、双引号、`$'...'`、续行，以及 `-X`、`-H`、`-d` 和各种 `--data-*`、`-F`、`-u`、`-b`、`--compressed`、`-k`、`-L`、`--url`；其他参数会作为提示列出。导出请求时，可以保留 `{{变量}}`，也可以按当前环境替换（包括敏感值）。
- **OpenAPI 3.0 与 3.1**（YAML 或 JSON）：每个 operation 生成一个请求，按第一个 tag 分组，带上路径、查询和请求头参数以及 JSON 请求体示例。响应示例可以生成快照，`servers[0]` 可以写入某个环境组的 `baseUrl`。导出分组时每个请求成为一个 operation，快照写成响应的 `examples`；二进制快照不导出。不支持 Swagger 2.0。

## 用 Cookie jar 保持登录

激活环境组后，每次发送都会把服务端设置的 cookie 存进该环境组的 Cookie jar，之后的请求自动带上匹配的 cookie，重定向过程中也一样。先发登录请求，再发其他请求即可。

- cookie 按域名、路径、`Secure` 和过期时间匹配；`Max-Age=0` 与过去的 `Expires` 会删除 cookie。`Domain` 不覆盖请求主机时忽略。
- 请求里手写的 `cookie` 头会与 jar 合并，同名时以手写的为准。
- 请求「设置」里的「不使用环境组的 Cookie jar」可以对单个请求关闭它。
- 环境组面板列出已保存的 cookie（不显示值），可以删除单个或全部。它们保存在 `environments/secret/cookies/<组>.json`，和其他敏感值一样不进版本库。

## 用环境组填充请求

右栏管理 `dev`、`test` 这样的环境组。在「激活的环境组」里选中一个，就会使用它的变量。

变量由外向内查找，内层的值覆盖外层：先是激活的环境组，再是外层到内层各分组的变量，最后是请求自己的变量。

令牌不要直接写进环境组文件，写成占位符：

```json
{ "vars": { "baseUrl": "https://dev.example.com", "token": "<secret:dev_token>" } }
```

再在「敏感值来源」里配置来源 `dev_token`：可以是一个明文值，也可以是 mock 服务进程的某个环境变量名。管理页从不显示敏感值，解析预览也只显示占位符；敏感值来源只能在本机打开的管理页里修改。

## 提交调试页写出的文件

所有数据都在 mock 目录的 `__debug__/` 下，mock 加载和热更新都会忽略它。

| 路径 | 内容 | 是否提交 |
| --- | --- | --- |
| `__debug__/requests/` | 分组与请求：`req.json` 是请求定义，`__meta__.json` 是展示名、权重与变量；快照在每个请求的 `res/<名称>/` 下 | 提交 |
| `__debug__/environments/<组>.json` | 环境变量，敏感值写成 `<secret:id>` 占位符 | 提交 |
| `__debug__/environments/secret/` | 敏感值来源，包括明文值 | 不提交；加进 `.gitignore` |
| `__debug__/history/` | 每次发送：实际发出的请求、响应头，响应体单独存为文件 | 不提交；加进 `.gitignore` |

敏感值来源和历史目前以明文保存，包括实际发出的 `authorization` 请求头，所以不要把 `environments/secret/` 和 `history/` 提交进版本库。
