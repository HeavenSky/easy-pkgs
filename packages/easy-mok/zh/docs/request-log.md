# 查看请求并存为 mock

[English](../../docs/request-log.md) · **简体中文**

读完本页，你能分清一个请求是走了 mock、被放行还是没命中，并把任何一次捕获到的响应变成 mock。请求日志在管理页 `/__mock/` 里，悬浮条上能看到最近命中的请求。

## 阅读请求日志

![请求日志与单个请求的详情面板](../../docs/images/logs.png)

日志记录命中 mock 的请求、被放行的请求，以及未命中的浏览器 fetch/XHR 请求，请求与响应细节完整可查。用 gzip、deflate、br 或 zstd 压缩的响应体会解码后显示。`authorization`、`cookie` 等敏感头会脱敏。

未命中的请求只在来自 fetch 或 XHR 时记录，也就是带有 `sec-fetch-dest: empty` 或 `x-requested-with: XMLHttpRequest` 请求头。Chrome DevTools 的探测请求也带 `sec-fetch-dest: empty`，所以要靠忽略规则排除，见[给请求日志降噪](ignore-rules.md)。

## 把响应变成 mock

1. 在日志里点开一个请求，查看详情面板。
2. 命中了路由的请求，点「存为该路由的场景」，场景写入 mock 目录下的 `__scenes__/`。
3. 未命中的请求，点「为此请求新建 mock」，以它为起点新建路由。

只有完整捕获、没有被截断的响应才能存为场景。

## 把请求发往真实后端

在日志详情里点「转为调试请求」，会在「调试」页生成一个请求，之后可以把它发往真实后端并保存结果，见[在管理页调试真实接口](debug.md)。它的 URL 写成 `{{baseUrl}}` 加原来的路径和查询参数，请在环境组里设置 `baseUrl`。

日志会对 `authorization`、`cookie` 等请求头脱敏，所以这些头不会带入，并作为提示列出，请在请求或环境组里补上。二进制和被截断的请求体也不会带入。

## 了解日志保留多少

每条日志最多捕获 256 KB 响应体和 64 KB 请求体，足够覆盖常见的 JSON 接口。日志默认保留最近 500 条（选项 `logSize`），全部条目的请求体与响应体合计不超过 32 MB，超出时淘汰最旧的条目。没有这个上限时，500 条日志最坏会占用约 160 MB 内存。
